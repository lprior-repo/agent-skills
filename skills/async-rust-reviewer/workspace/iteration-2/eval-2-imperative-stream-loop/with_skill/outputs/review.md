# Async Rust Review: crates/infra/src/event_processor.rs
**Mode**: SNIPPET | **Date**: 2026-04-03

## VERDICT: REJECTED

## LETHAL FINDINGS (3)

1. **[streams_over_loops] crates/infra/src/event_processor.rs:7** -- Imperative stream loop `while let Some(event) = stream.next().await`. This is the exact banned pattern from rule `streams_over_loops`. Streams are the async counterpart to Iterators; they MUST be consumed via combinator pipelines (`.filter()`, `.map()`, `.buffer_unordered(N)`, `.for_each_concurrent(N)`), not hand-rolled while loops. This loop processes events one at a time, entirely wasting I/O concurrency. Replace with a functional pipeline. See `references/stream-patterns.md` for the combinator cookbook.

2. **[bounded_concurrency] crates/infra/src/event_processor.rs:7-12** -- No concurrency bound exists anywhere in this function. Even after refactoring away the imperative loop, there is no `buffer_unordered(N)`, no `for_each_concurrent(N)`, no semaphore. Unbounded concurrency on a dynamic collection is a denial-of-service vector that will OOM the service under load. Every concurrent operation MUST have an explicit bound. See `references/stream-patterns.md` for the concurrency primitive decision matrix.

3. **[arc_over_rc] crates/infra/src/event_processor.rs:5** -- `Rc<ProcessingContext>` is held across `.await` points at lines 7 and 9. `Rc<T>` is `!Send`. The future generated by this `async fn` will therefore be `!Send`, which fails to compile on Tokio's multi-threaded runtime. Even on a single-threaded runtime, `Rc` across `.await` is banned by `clippy::await_holding_refcell_ref` category. Replace with `Arc<ProcessingContext>`. See `references/send-sync-ownership.md` for the Arc vs Rc decision table.

## MAJOR FINDINGS (4)

1. **[tracing_instrument] crates/infra/src/event_processor.rs:4** -- This async infrastructure function has no `#[tracing::instrument]` and no explicit span creation. Bare `.await` without surrounding span loses the causal chain across async boundaries. Every async function in the shell MUST be instrumented. See `references/observability-reference.md` for `#[instrument]` patterns.

2. **[async_error_chain] crates/infra/src/event_processor.rs:9** -- `process(enriched).await` produces a result that is blindly pushed into the `results` Vec with no error inspection. If `process` is an I/O operation (which it almost certainly is at the infra layer), it can fail. Errors are silently accumulated without context. Use `.map_err()` or `?` propagation. See `references/observability-reference.md` for error chain preservation patterns.

3. **[cancellation_safe_design] crates/infra/src/event_processor.rs:8-9** -- `context.enrich(event)` runs synchronously, then `process(enriched).await` suspends. If the future is dropped at that `.await`, the enriched event has been created but never processed. Whether this matters depends on whether `enrich` has side effects, but the pattern of "prepare sync, then await" without a documented recovery plan violates cancellation-safe design. See `references/cancellation-safety.md` for two-phase commit patterns.

4. **[no_imperative_concurrency / Async Sniff Test] crates/infra/src/event_processor.rs:7-12** -- The function processes events sequentially. The async stream provides zero concurrency benefit. Either use bounded concurrency via combinators, or justify why strict ordering is required. A sync function iterating a `Vec<Event>` would be simpler and equally correct if ordering is the goal. See `references/stream-patterns.md` for `buffer_unordered` and `for_each_concurrent` examples.

## MANDATE

1. **Replace `Rc` with `Arc`** -- Change `use std::rc::Rc` to `use std::sync::Arc` and `Rc::new(...)` to `Arc::new(...)`. Non-negotiable for multi-threaded Tokio. See `references/send-sync-ownership.md`.

2. **Replace the imperative loop with a combinator pipeline** -- Remove `while let Some(event) = stream.next().await`. Use `stream.filter().map().buffer_unordered(N)` or `.for_each_concurrent(N, ...)` with an explicit concurrency bound (e.g., N=32). See `references/stream-patterns.md` for the combinator cookbook and decision matrix.

3. **Fix the return type** -- Add `-> Result<Vec<ProcessResult>, SomeError>` to the function signature.

4. **Add `#[tracing::instrument]`** -- Annotate with `#[tracing::instrument(skip(stream))]` or equivalent. See `references/observability-reference.md`.

5. **Handle errors from `process(enriched).await`** -- Propagate with `?` or explicitly handle with `.map_err()`. Never silently collect results without error inspection. See `references/observability-reference.md` for error chain preservation.

6. **Add criterion benchmarks** -- Create throughput baselines at N=1, N=8, N=64 concurrency levels. No numbers = no merge. See `references/benchmark-patterns.md` for async benchmark templates.

7. **Verify cancellation safety** -- Document what happens if the future is dropped mid-enrichment or mid-processing. Use two-phase commit if side effects are involved. See `references/cancellation-safety.md`.
